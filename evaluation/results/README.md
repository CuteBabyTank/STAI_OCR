# Evaluation results

**Empty by design at the time of writing — no evaluation run has been executed.**
Creating this directory does not create evidence.

| Directory | Contents |
|---|---|
| `raw/` | One file per run, exactly as produced. Includes failed and errored cases. |
| `processed/` | Derived metric tables and summaries computed from `raw/`. |
| `failures/` | Failure taxonomy output and case studies. |

## Rules

1. **Result files are tracked in git.** Unlike `evaluation/fixtures/*.db` (build
   artifacts, regenerated by a versioned seeder), a result cannot be regenerated — it
   records what a specific model did at a specific moment. The breakdown requires
   versioned evidence, so these are committed.
2. **Every file carries its configuration.** `evaluation.report.write_result` attaches
   the runtime capture (commit, resolved model names, endpoint, database hash) plus
   any `configuration_gaps`. A number without that context is not evidence.
3. **Failures stay.** Deleting a failed case to improve a rate invalidates the whole
   result set. `summarize()` retains failed case ids.
4. **A rate with no cases is `None`, never 0 or 1.** An unmeasured metric must not be
   reported as a measured one.

## Producing results

```bash
# Print the tested-configuration capture and any reproducibility gaps
./.venv/bin/python -m evaluation.report config

# Validate the trajectory case file without calling a model
./.venv/bin/python -m evaluation.trajectory --dry-run

# Live trajectory run (requires a reachable Ollama) -> writes to raw/
./.venv/bin/python -m evaluation.trajectory
```

Fill `vision_model_digest` / `agent_model_digest` from `ollama list` on the serving
host before treating any run as reproducible: `:latest` is mutable and does not
identify a model.
